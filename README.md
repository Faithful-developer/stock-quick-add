# Stock Quick Add

Chrome-расширение (Manifest V3, боковая панель) для приёма остатков по штрихкоду
и смены способа оплаты продажи в OX. Без сборки: репозиторий и есть расширение.

Extension ID (закреплён через `key` в манифесте): `hnmnpodpdcpamjcfdaiplppajkigfdnb`

## Установка (один раз)

1. Включите **Developer mode** на `chrome://extensions` (переключатель справа вверху).
2. Склонируйте репозиторий в **постоянную** папку. Не в Downloads и не на рабочий стол:
   если папку удалить, расширение перестанет работать.

   ```bash
   git clone https://github.com/Faithful-developer/stock-quick-add.git ~/stock-quick-add
   ```

3. На `chrome://extensions` нажмите **Load unpacked** и выберите папку `~/stock-quick-add`
   (ту, где лежит `manifest.json`).
4. Откройте настройки расширения и заполните профиль: поддомен, токен, склад.
5. Горячая клавиша: `Ctrl+Shift+S` (macOS) / `Alt+Shift+S` (Windows, Linux).
   Изменить: `chrome://extensions/shortcuts`.

## Обновление

```bash
cd ~/stock-quick-add && git pull
```

Затем на `chrome://extensions` нажмите значок **Reload** (↻) на карточке Stock Quick Add.
Если открыта боковая панель, закройте и откройте её заново.

## Что нужно знать

- **Developer mode** должен оставаться включённым. При запуске Chrome показывает окно
  «Disable developer mode extensions». Нажимайте **Cancel**. Кнопка **Disable** отключит
  расширение, и его придётся включить вручную на `chrome://extensions`.
- **Автообновлений нет.** Кто не сделал `git pull`, работает на старой версии.
  Номер установленной версии виден на карточке расширения; актуальный номер — в
  `manifest.json` в этом репозитории.
- **ID расширения одинаковый у всех**, потому что в манифесте закреплён публичный ключ.
  Не удаляйте поле `key` из `manifest.json`.

## Для сопровождающих

### Главное правило: сохранённые компании переживают любой релиз

Профили компаний (субдомен, токен, склад) лежат в `chrome.storage.local` и
привязаны к ID расширения. Оператор настраивает их один раз и не должен
повторять после обновления. Поэтому:

- **Не трогайте поле `key` в `manifest.json`.** Смена ключа меняет ID, и Chrome
  считает расширение новым: хранилище пустое, все компании «пропали».
  Именно это случилось при переходе на 2.3.0.
- **Не переименовывайте и не удаляйте ключи `profiles` и `activeProfileId`**
  без миграции на месте. Миграция запускается из `sw.js` на `onInstalled`,
  должна быть безопасной при повторном запуске и никогда не удалять данные,
  которые не смогла перенести (пример: `migrateLegacy()` в `profiles.js`).
- **Никогда не вызывайте `chrome.storage.local.clear()`.**
- Изменение формы хранилища проверяйте так: установить старую версию, завести
  две компании, сделать `git pull` + Reload, убедиться, что обе на месте.


- Приватный ключ, из которого сгенерирован `key`, хранится **вне репозитория**
  (`~/.stock-quick-add-keys/stock-quick-add.pem` у автора). Он нужен только для сборки
  `.crx`; для загрузки unpacked достаточно публичного ключа в манифесте.
- При каждом изменении поднимайте `version` в `manifest.json`, чтобы на карточке было
  видно, кто на какой версии.
